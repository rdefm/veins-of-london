# 02 — Combat-pattern consumables: healingSalve, blast, shield, blackHole, healingBurst

**What to build:** Five of the ten discoverable-but-unwired lab effects (`data/recipes.json` already has full recipe data and discovery cells for all of them per the calc-discovery feature) get real gameplay effects and become usable, not just craftable-and-sellable. Today only `timePearl`, `enhancementPowder`, and `rewind` are wired into combat and the only three items shown on the inventory Consumables tab (hardcoded list, `scenes/screens/inventory.gd:65`) — this ticket brings five more effects up to the same "craft it, see it, use it" bar.

**Blocked by:** 01 — Enemy combat capabilities (Blast's disarm sub-behaviour strips an enemy's weapon/ability, which ticket 01 makes possible; the other four effects in this ticket don't themselves need 01).

- [ ] **healingSalve** (out-of-combat, 2-day heal-over-time): using it sets a duration state (e.g. `player.healingSalveDaysLeft = 2`, `player.healingSalveDailyAmount = effect_power("healingSalve", skill)`). `TimeSystem.daily_tick()` gets a new step that, while `daysLeft > 0`, heals `dailyAmount` HP (capped at `hpMax`) and decrements `daysLeft`. Using a second salve while one is active **refreshes** to 2 days at the new daily amount — does not stack a second concurrent HoT.
- [ ] **blast** (combat): on use, deal `effectPower(skill)` damage to the enemy immediately; boost the *next* `combat_flee()` attempt's success chance (e.g. to 0.90) for one use, then clear; roll a small disarm chance (e.g. 15%) that calls ticket 01's `Combat.disarm_enemy()` for a short duration on success. Exact percentages are placeholders for this ticket to tune, not final balance.
- [ ] **shield** (combat): on use, immediately deducted from inventory, sets `player.shieldPool = effectPower(skill)` (no turn cap). While `shieldPool > 0`, incoming enemy attack damage is absorbed from the pool 1:1 (`dmg <= pool` → pool -= dmg, player takes 0; `dmg > pool` → player takes `dmg - pool`, pool = 0). Using a second shield while a pool is still active is blocked (same "already active" guard shape as Time Pearl's `combat.gd:274`).
- [ ] **blackHole** (combat): on use, deal `effectPower(skill)` damage immediately, and add to the shared `frozenTurns` field a duration derived from `effectPower` via a formula (no new per-recipe schema field — e.g. `1 + floor(effectPower / 8)`, tune as needed). This is always additive to `frozenTurns` regardless of source (stacks with Time Pearl or a prior blackHole) — no reuse guard.
- [ ] **healingBurst** (usable in or out of combat): instant heal, `hp = min(hp + effectPower(skill), hpMax)`, consumed immediately. No duration, no secondary behaviour.
- [ ] Inventory's Consumables tab (`scenes/screens/inventory.gd`) stops hardcoding `["timePearl", "enhancementPowder", "rewind"]` — iterates every recipe key with `inventory[key] > 0` instead, so all five new effects (and any future ones) show up without another hardcoded-list edit. Include `rejuvenation` in this iteration too (sale-only, no `Use` action, but should be visible/sellable from the same tab) while touching this code.
- [ ] Combat screen gains `Use` actions for blast/shield/blackHole/healingBurst alongside the existing Time Pearl/Enhancement Powder buttons; healingSalve/healingBurst get a `Use` entry outside combat too (healingBurst) / on the inventory card (healingSalve).
- [ ] `tests/test_combat.gd`, `tests/test_bench.gd` or equivalent extended: each of the five effects' success-path mechanics (damage, absorb/overflow math, freeze-stacking, HoT tick-and-refresh, instant heal), plus the inventory tab's dynamic listing.
- [ ] Syntax check clean; full test suite green.
