# 03 — Reactive and escape consumables: prophetsBreath, failsafe, wormhole (partial)

**What to build:** Three more of the ten unwired lab effects, trimmed to the sub-behaviours that fit systems which already exist — each effect's full flavor-text scope goes further than this (see the follow-up-specs index), but this ticket ships the parts that don't require inventing a new system first.

**Blocked by:** None — independent of tickets 01/02, can run in parallel.

- [ ] **prophetsBreath** (combat evade-buff only): on use, `evadeTurns = effectPower(skill)` (the recipe's own effectPower array, `[0,1,1,2,2,3]`, already reads as a turn count), `evadeChance = 0.50` — same value as Rewind's existing evade grant (REFERENCE.md §3.9), sharing the `evadeTurns`/`evadeChance` fields. Activating this while those fields are already active from Rewind (or vice versa) **overwrites** both to the new activation's values — no stacking/reconciliation logic. Prophet's Breath's event-preview half (peek-rolling a choice's chance before committing) is explicitly out of scope — see follow-up spec.
- [ ] **failsafe** (reactive, auto-triggered): no manual `Use` action. The moment the player's HP would hit 0 (in any combat context), if `inventory.failsafe > 0`, auto-consume one and call the existing Rewind snapshot-restore path (`combat_rewind()`'s "restore the oldest of the 2 stored snapshots" logic, REFERENCE.md §3.9) instead of letting the "loss" outcome resolve. This is checked and resolved *before* a manually-held Rewind consumable or equipped Rewind device — failsafe is a separate resource, always tried first when HP would hit 0.
- [ ] **wormhole** (partial — combat flee + trigger-free travel): in combat, guarantees `combat_flee()` succeeds (bypass the 0.65 roll and the enemy's free-attack-on-failed-flee). On the map, using it to travel to a district calls the existing `Travel.travel_to()` path but **skips** `DistrictDeck.maybe_trigger()` and `Raiding.maybe_trigger_defend()` — arrives with zero chance of a random arrival encounter, which normal (already-free) travel can't do. The raid-alert/instant-HQ-escape clause is explicitly out of scope — see follow-up spec.
- [ ] Combat screen gains `Use` buttons for prophetsBreath and wormhole (flee). Map/travel UI gains a wormhole option on district travel, consuming one on use. Failsafe needs no UI beyond showing up in the inventory Consumables tab (ticket 02 already generalizes that listing) — its use is entirely automatic.
- [ ] `tests/test_combat.gd` / `tests/test_events.gd` (or equivalent) extended: prophetsBreath's evade-grant and overwrite-on-reuse behaviour; failsafe's auto-trigger-before-loss-outcome path, including the event-embedded-raid case; wormhole's guaranteed flee and trigger-free travel (asserting `DistrictDeck.maybe_trigger`/`Raiding.maybe_trigger_defend` are not called on a wormhole trip).
- [ ] Syntax check clean; full test suite green.
