# M1.5 — The Network (map rendering)

**Goal:** replace M1's plain-list Map tab with the real Beck-style transit-diagram renderer, against the exact interaction contract M1 already shipped (district panel, site/vein sheet, tap targets — see `docs/M1-LONDON.md` D4). This milestone renders; it does not redesign navigation, add mechanics, or touch `GameState`.

**Why this is its own milestone, not part of M1:** see `docs/adr/0001-defer-network-map-renderer.md`. In short — this is the only part of the original M1 plan that is expensive to build, hard to reverse once built, and verifiable only by on-device visual QA; everything else in M1 is headlessly testable. Splitting it out let the economy loop (districts, prospecting, event deck, tutorial) ship and be verified on its own.

**Depends on:** M1 complete — districts, sites, travel, the nav shell (Map · HQ · Phone · Bag · You), the district panel, the site/vein sheet, BagDrawer, and The Ticker all already exist and are being reused here, not rebuilt.

Same rules of engagement as M0/M1. This doc extends `docs/REFERENCE.md` and `docs/M1-LONDON.md`; on conflict for Network Map rendering specifically, this doc wins.

## N1 — Legal + visual guardrails

Beck-style octilinear diagrams are a generic design language — but NEVER: TfL roundels, the actual tube map's layout, real line names, or real line-name/colour pairings, and never "the Underground"/"London Underground" as the name of the map, the network, or any feature (registered TfL marks). Lowercase descriptive use in dialogue is fine ("the underground trade"). Do not describe it as "the tube map" in any player-facing string; in-game it is **"the Network"** (this naming rule already applies in M1's plain-list Map tab — see `docs/M1-LONDON.md` D4).

## N2 — Semantic channels (fixed grammar — do not vary)

- **LINES = ownership.** An owner's stops in adjacent districts are joined into that owner's line. Colours: player = amber #c8873a; each faction = its `colour` from factions.json; NPC-claimed (unaffiliated) stops = short grey #8a8a8a stubs, unconnected. Unclaimed discovered sites render as stops too (see below) but carry no line — never joined to any owner's route.
- **STOPS = veins and sites.** Glyph grammar (logical px):
  - Your vein / faction vein: circle r7, stroke 2.5 in owner colour, paper fill; the ore SYMBOL (⧖ ↯ ✦ ⚄ ❋) centred, drawn in the ore's type colour. Symbol carries type (colour-blind safe).
  - Unclaimed site (bugfixes ticket 27 — human sign-off superseded the tick-mark grammar below): same paper-fill circle + ring shape as a claimed stop, ring in `--muted`, ore symbol centred — "looks like an underground stop, just not connected to any line." Rich/Saturated sites: a second, concentric ring (interchange styling), same idea as the old double tick just ported to the ring shape.
  - NPC-claimed site: filled grey dot r5, no symbol ("someone else's problem now").
  - Charged vein: soft amber halo behind the stop, tween pulse (scale 1.0→1.3, alpha 0.5→0, 1.2 s loop).
  - Vein level: small numeral 1–6 in a badge at the stop's 4 o'clock.
  - Security: padlock micro-icon at 8 o'clock, tinted by tier (none = absent, basic `--muted`, warded #7b68ee, guarded `--success`).
- **ZONE FILLS = faction presence.** District `zonePolygon` filled at 8% alpha in the presence faction's colour (static in M1/M1.5; relation-reactive in M5).
- **PINS = points of interest.** Home/property icon at the home district (tap → HQ); contact pin when an event awaits at an address (tap → start that event); Soho market pin, padlocked until M4; player-position marker ("You are here" ring) on `currentDistrict`.

## N3 — Rendering & layout data

- `data/map_layout.json`: `{ mapSize:[1170,1560], districts:{ id:{ anchor:[x,y], labelAnchor:[x,y], zonePolygon:[[x,y],…], stopSlots:[[x,y],…] } }, riverPath:[[x,y],…], homeAnchor:[x,y] }`. Coordinates in logical map px (map canvas is 3× the 390 column, inside a pan-capable `Camera2D`/ScrollContainer; pinch-zoom is a stretch goal, pan is required). Hand-place plausible-London coordinates; geographic exactness irrelevant. Each district has ≥ `siteCap + 2` stopSlots; stops occupy slots in discovery order.
- **Octilinear line routing (deterministic):** for each owner, order their stops nearest-neighbour starting from `homeAnchor` (player) or the faction's first-presence district anchor. Connect consecutive stops with a two-segment elbow: diagonal 45° for `min(|dx|,|dy|)`, then axis-aligned for the remainder (pick the elbow orientation that avoids crossing the river path where trivially possible; otherwise ignore crossings — the real thing crosses lines constantly). `Line2D`: width 6, round caps/joints, corner radius via joint mode. A single-stop owner draws a 24 px terminus stub through the stop at 45°.
- **River:** `riverPath` drawn once, width 14, colour #d4cfc4 at 60% alpha, beneath everything but the paper.
- Draw order: paper → zones → river → lines → stops → badges/halos → pins → labels. District labels in the UI sans, `--slate`, small caps.
- All drawing in one `MapCanvas` Control using `_draw()` + a handful of child nodes for pulsing halos and pins; rebuilt from state on `state_changed`. No per-stop scenes; keep it immediate-mode and dumb.

## N4 — Filters (view modes)

A chip row above the map: **Ownership · Type · Strength · Charge · Security**. One active at a time; default Ownership. Modes re-style ONLY (never hide stops, never change tap behaviour):
- Ownership: the default grammar above (lines coloured by owner).
- Type: all lines/stubs desaturate to `--muted`; stop rings recolour by ore type; symbols stay.
- Strength: stop ring thickness 1.5 + level×0.8; ring greyscale ramp from `--muted` (L1) to `--ink` (L6); level badges enlarge.
- Charge: charged stops full colour + halo; everything uncharged drops to 35% alpha; per-stop countdown badge "2⏳" = blocks until charged.
- Security: padlock badges enlarge; unsecured YOUR veins get a `--danger` dotted ring (the "you should fix this" view).
Filter is UI-local state (not saved, not in GameState).

## N5 — Interaction (delta over M1's plain-list Map)

M1 already ships the district panel and site/vein sheet (`docs/M1-LONDON.md` D4's "Map tab" section) — this milestone doesn't change their content, only how you get to them:
- Tap stop/tick on the diagram → the same **site/vein sheet** M1 already built (unchanged).
- Tap district label or zone → the same **district panel** M1 already built (unchanged).
- Tap pin → its screen/event (new — M1's plain list had no pins). Legend button (?) → modal titled "Network Reference", listing the glyph grammar with one dry line of flavour (DRAFT, PROSE-REVIEW).

## N6 — Asset list (total, final)

1. **Paper texture** — 1536×2048 PNG, aged cream (#f0ece2 family), subtle foxing/grain, NO linework, NO text. AI-generatable; also acceptable: procedural noise over flat colour as placeholder.
2. **Icon glyphs ×8** — home, pin, padlock, market, phone, bag, legend "?", news: 64 px, single-colour (tint in engine). Draw as simple `_draw()` polygons if no pack is available.
   - **+1 (bugfixes ticket 13): hamburger.** The Map tab's own top bar (not part of this milestone's original scope) used a "☰" text glyph for its menu button, which — like every other non-ASCII glyph tried in this project — renders as nothing on the exported build's font. Fixing an on-device invisible-button bug needed a real glyph, not new content, so this is a deliberate, approved exception to "exactly 8, nothing added" below, not scope creep. Same draw style/scale conventions as the other 8.
3. Fonts already bundled (M0). Ore symbols are text glyphs — verify the bundled font covers ⧖ ↯ ✦ ⚄ ❋ on Android; if not, render them as tiny SVG-derived textures (add to icon set).

Nothing else beyond the 8 (+1, see above). There is no commissioned illustration in this design.

## Task order

T1 map layout data + MapCanvas rendering (lines/stops/zones/river; +tests: octilinear elbow geometry pure functions, nearest-neighbour ordering determinism, stop-slot assignment) → T2 filter modes (5) + pins + legend modal (human visual QA per filter mode) → T3 asset production/integration (paper texture, icon glyphs, ore-symbol font coverage check on Android) → T4 swap M1's placeholder Map-tab list for the real diagram; verify district panel / site-vein sheet / pin tap targets are unchanged from M1.

## M1.5 exit criteria

1. The Network map renders correctly from any save state (including debug start) — every ownership change, discovery, seed, charge and security change appears without restart; a newly seeded vein visibly joins the player's line.
2. All five filter modes correct on device; ore symbols legible at 1× on a real phone.
3. Tap targets (stop, district zone/label, pin, legend) behave identically to M1's placeholder list UI — no interaction regressions against the district panel or site/vein sheet.
