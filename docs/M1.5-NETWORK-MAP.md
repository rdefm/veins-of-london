# M1.5 — The Network (map rendering)

**Goal:** replace M1's plain-list Map tab with the real Beck-style transit-diagram renderer, against the exact interaction contract M1 already shipped (district panel, site/vein sheet, tap targets — see `docs/M1-LONDON.md` D4). This milestone renders; it does not redesign navigation, add mechanics, or touch `GameState`.

**Why this is its own milestone, not part of M1:** see `docs/adr/0001-defer-network-map-renderer.md`. In short — this is the only part of the original M1 plan that is expensive to build, hard to reverse once built, and verifiable only by on-device visual QA; everything else in M1 is headlessly testable. Splitting it out let the economy loop (districts, prospecting, event deck, tutorial) ship and be verified on its own.

**Depends on:** M1 complete — districts, sites, travel, the nav shell (Map · HQ · Phone · Bag · You), the district panel, the site/vein sheet, BagDrawer, and The Ticker all already exist and are being reused here, not rebuilt.

Same rules of engagement as M0/M1. This doc extends `docs/REFERENCE.md` and `docs/M1-LONDON.md`; on conflict for Network Map rendering specifically, this doc wins.

## N1 — Legal + visual guardrails

Beck-style octilinear diagrams are a generic design language — but NEVER: TfL roundels, the actual tube map's layout, real line names, or real line-name/colour pairings, and never "the Underground"/"London Underground" as the name of the map, the network, or any feature (registered TfL marks). Lowercase descriptive use in dialogue is fine ("the underground trade"). Do not describe it as "the tube map" in any player-facing string; in-game it is **"the Network"** (this naming rule already applies in M1's plain-list Map tab — see `docs/M1-LONDON.md` D4).

## N2 — Semantic channels (fixed grammar — do not vary)

- **LINES = ownership.** An owner's stops in adjacent districts are joined into that owner's line. Colours: player = amber #c8873a; each faction = its `colour` from factions.json; NPC-claimed (unaffiliated) stops = short grey #8a8a8a stubs, unconnected. Unclaimed discovered sites render as stops too (see below) but carry no line — never joined to any owner's route.
- **STOPS = veins and sites.** Glyph grammar (logical px):
  - Your vein / faction vein: circle r7, paper fill; the ore SYMBOL (⧖ ↯ ✦ ⚄ ❋) centred, drawn in the ore's type colour. Symbol carries type (colour-blind safe). The ring itself is a **radial growth fill** (bugfixes ticket 77, replacing vein-growth-state ticket 07's growth-gauge arc and the 4 o'clock days-to-wall badge) — see below.
  - Unclaimed site (bugfixes ticket 27 — human sign-off superseded the tick-mark grammar below): same paper-fill circle + ring shape as a claimed stop, ring in `--muted`, ore symbol centred — "looks like an underground stop, just not connected to any line." Rich/Saturated sites: a second, concentric ring (interchange styling), same idea as the old double tick just ported to the ring shape. Unclaimed sites have no growth, so they keep this plain, always-styled ring rather than the growth-fill treatment below.
  - NPC-claimed site: filled grey dot r5, no symbol ("someone else's problem now").
  - **Growth fill** (bugfixes ticket 77): a radial fill sits behind the ore icon, its fill level a direct proportion of `growth / ceiling(vein)` — empty at growth 0, full at the ceiling — flat-coloured in the stop's owner colour (player amber, or the owning faction's colour), never gradiented or textured by growth band. A thin full-circumference outline in the same colour always draws, so the stop's extent still reads even at growth 0. This replaces the old growth-gauge arc (12 o'clock sweep, per-band serrated/gapped/plain edge texture) and the 4 o'clock days-to-wall badge outright — the days-to-wall figure isn't relocated anywhere on the map, only the site sheet's raw "Growth: X/Y" text/bar (`docs/M1-LONDON.md` D4) still carries it. Fill colour otherwise follows the active filter the same way the old ring did (ore colour under Type, a `value_tier` greyscale ramp under Growth).
  - Terroir (vein-growth-state ticket 05 amplification, ticket 07 rendering): a player/faction vein on rich/saturated land draws the same second, concentric interchange ring an unclaimed rich/saturated site draws — the old 4 o'clock level badge did not carry this; it's dropped entirely, not repurposed.
  - Wild/rampant vein: soft amber halo behind the stop, tween pulse (scale 1.0→1.3, alpha 0.5→0, 1.2 s loop) — the growth-model successor to the old "charged vein" halo, now keyed on the vein sitting in the `wild`/`rampant` growth bands rather than a recharge-block countdown.
  - Security: padlock micro-icon at 8 o'clock, tinted by tier (none = absent, basic `--muted`, warded #7b68ee, guarded `--success`).
- **ZONE FILLS = faction presence.** District `zonePolygon` filled at 8% alpha in the presence faction's colour (static in M1/M1.5; relation-reactive in M5).
- **PINS = points of interest.** All pins share the same teardrop marker (`Icons.draw_pin`) — a different silhouette from every STOP glyph above (which are all circles) — with a second icon layered on the marker's head and a colour, both distinct per pin kind so pins also read apart from each other, not just from stops:
  - Home/property icon (amber, player colour) at the home district (tap → HQ).
  - Contact pin (bugfixes ticket 49: phone icon, `--warded` #7b68ee) when an event awaits at an address (tap → start that event).
  - Soho market pin (grey `--muted`, padlock icon), padlocked until M4 — no tap action yet.
  - Guild Marketplace pin (bugfixes ticket 49: bag icon, `--success` #3a7a52) at the Guild's own faction-presence district (tap → the existing `GuildMarketplaceScreen`, which renders its own locked state for non-members) — additive to that screen's pre-existing route via the Guild's faction card, not a replacement for it.
  - Player-position marker ("You are here" ring) on `currentDistrict` — not a pin, not a tap target.

## N3 — Rendering & layout data

- `data/map_layout.json`: `{ mapSize:[1170,1560], districts:{ id:{ anchor:[x,y], labelAnchor:[x,y], zonePolygon:[[x,y],…], stopSlots:[[x,y],…] } }, riverPath:[[x,y],…], homeAnchor:[x,y] }`. Coordinates in logical map px (map canvas is 3× the 390 column, inside a pan-capable `Camera2D`/ScrollContainer; pinch-zoom is a stretch goal, pan is required). Hand-place plausible-London coordinates; geographic exactness irrelevant. Each district has ≥ `siteCap + 2` stopSlots; stops occupy slots in discovery order.
- **Octilinear line routing (deterministic):** for each owner, order their stops nearest-neighbour starting from `homeAnchor` (player) or the faction's first-presence district anchor. Connect consecutive stops with a two-segment elbow: diagonal 45° for `min(|dx|,|dy|)`, then axis-aligned for the remainder (pick the elbow orientation that avoids crossing the river path where trivially possible; otherwise ignore crossings — the real thing crosses lines constantly). `Line2D`: width 6, round caps/joints, corner radius via joint mode. A single-stop owner draws a 24 px terminus stub through the stop at 45°.
- **River:** `riverPath` drawn once, width 14, colour #d4cfc4 at 60% alpha, beneath everything but the paper.
- Draw order: paper → zones → river → lines → stops → badges/halos → pins → labels. District labels in the UI sans, `--slate`, small caps.
- All drawing in one `MapCanvas` Control using `_draw()` + a handful of child nodes for pulsing halos and pins; rebuilt from state on `state_changed`. No per-stop scenes; keep it immediate-mode and dumb.

## N4 — Filters (view modes)

A chip row (now a drawer, per map-filters ticket 03) above the map: **Ownership · Type · Growth · Security**, plus map-filters ticket 04's Faction isolate. One active at a time; default Ownership. Modes re-style ONLY (never hide stops, never change tap behaviour):
- Ownership: the default grammar above (lines coloured by owner).
- Type: all lines/stubs desaturate to `--muted`; stop rings recolour by ore type; symbols stay.
- Growth (vein-growth-state ticket 07 — merges the old Strength and Charge chips into one): fades every stop outside the "risk" bands (`barren`/`sparse`/`wild`/`rampant`/`collapsed`) to 35% alpha, keeping the bands worth watching at full colour; growth fill recolours to a `value_tier` greyscale ramp, `--muted` (tier 1) to `--ink` (tier 6) (bugfixes ticket 77: the old ring/arc's tier-based thickening doesn't carry over to the fill — there's no stroke left to thicken once the whole disc fills).
- Security: padlock badges enlarge; unsecured YOUR veins get a `--danger` dotted ring (the "you should fix this" view).
Filter is UI-local state (not saved, not in GameState).

## N5.5 — Event playback + pacing (map-animations tickets 01–06, renamed by bugfixes-50)

A discover/seed-claim/charge/drain/join-line event (site found, vein appears, growth crosses a threshold, a line segment grows on) doesn't just pop onto the map — it animates in via a queue, `state.mapEvents.queue`/`.playing` (`MapEvents`, `systems/map_events.gd`), drained by `MapCanvas` (`scenes/components/map_canvas.gd`) whenever the Map tab is open. Tapping the map mid-animation skips straight to the current event's end state and moves on.

**Pacing modes** — a drawer toggle (`map_controls.gd`'s "Pace" row), persisted at `state.mapEvents.pacingMode` (`MapEvents.pacing_mode()`/`set_pacing_mode()`) so it survives closing/reopening the Map tab and save/load, unlike the drawer's own filter mode:
- **`sequential`** (0.35s/event) — one event at a time: pan+zoom to it, play its visual, advance, repeat.
- **`simultaneous`** (1.5s, the default) — every event currently queued plays its visual at once instead of one-by-one. No forced camera pan/zoom in this mode (queued events can be at different map locations, so there's no single shot to cut to) — the camera stays wherever the player left it; any event outside the current view simply isn't seen animating, though its state still updates correctly once the batch resolves.

An event queued while a "simultaneous" batch is already animating doesn't join that batch — it waits and plays in the next one, once the current batch finishes and the queue is checked again.

## N6 — Asset list (total, final)

1. **Paper texture** — 1536×2048 PNG, aged cream (#f0ece2 family), subtle foxing/grain, NO linework, NO text. AI-generatable; also acceptable: procedural noise over flat colour as placeholder.
2. **Icon glyphs ×8** — home, pin, padlock, market, phone, bag, legend "?", news: 64 px, single-colour (tint in engine). Draw as simple `_draw()` polygons if no pack is available.
   - **+1 (bugfixes ticket 13): hamburger.** The Map tab's own top bar (not part of this milestone's original scope) used a "☰" text glyph for its menu button, which — like every other non-ASCII glyph tried in this project — renders as nothing on the exported build's font. Fixing an on-device invisible-button bug needed a real glyph, not new content, so this is a deliberate, approved exception to "exactly 8, nothing added" below, not scope creep. Same draw style/scale conventions as the other 8.
3. Fonts already bundled (M0). Ore symbols are text glyphs — verify the bundled font covers ⧖ ↯ ✦ ⚄ ❋ on Android; if not, render them as tiny SVG-derived textures (add to icon set).

Nothing else beyond the 8 (+1, see above). There is no commissioned illustration in this design.
